# سند انتقال نشست و ادامه گفتگو در لینوکس (Session Handover & Context Continuity)

این سند برای انتقال کامل کانتکست پروژه، تاریخچه گفتگو و تصمیمات طراحی از محیط **macOS** به **Linux** تنظیم شده است. با استفاده از این مستند یا انتقال فایل‌های مغز (Brain) ایجنت، می‌توانید پروژه را روی لینوکس دقیقاً با همان سطح هوشمندی و تسلط قبلی ادامه دهید.

---

## ۱. هویت برند و ضوابط بنیادین طراحی (Core Brand Rules)
1. **نام رسمی برند:**
   * انگلیسی: **Baldr** (حرف e در انتهای نام اشتباه بوده و در تمام کدها، فایل‌ها، متادیتاها و دایرکتوری‌ها به Baldr تغییر یافته است).
   * فارسی: **بالدر**
   * لوگو: نشان قرمز رنگ اختصاصی (`/images/baldr-logo-red.webp`) در نوبار و فوتر تمام صفحات نمایش داده می‌شود (نه متن خالی).

2. **هندسه تیز و بدون گردی (`rounded-none`):**
   * تمامی کامپوننت‌ها، دکمه‌ها، کارت‌های محصول، مدال‌ها، اینپوت‌ها و فیلترها باید گوشه‌های تیز داشته باشند (`rounded-none`). هیچ‌گونه گردی (`rounded-md`, `rounded-full`, etc.) مجاز نیست مگر دایره‌های کامل سواچ رنگ یا وضعیت رادیویی.

3. **فرمت اجباری تصاویر (`.webp`):**
   * تمامی عکس‌ها باید با فرمت `.webp` در `frontend/public/images/` ذخیره و فراخوانی شوند. استفاده از فرمت‌های سنگین `.jpg` و `.png` ممنوع است.

4. **تم بصری (Aesthetic):**
   * گالری روشن مینیمال با الهام از برندهای لوکس Flos و Davide Groppi با پس‌زمینه سفید/روشن، خطوط تفکیک ملایم (`#E5E5E5`) و رنگ اکسنت قرمز روشن (`#E40521`).

## ۳. آخرین وضعیت فیچرها و اصلاحات انجام‌شده
1. **جستارهای نوری (Lighting Essays):**
   * رکورد تکراری حذف شد و در اسکریپت `seed_baldr.py` پاک‌سازی خودکار قرار گرفت.
   * ۳ مقاله دارای کارت‌های تعاملی و لینک Next.js به صفحات هدف (`/products`، `/about`، `/professionals`) همراه با دکمه هاور «مطالعه و بررسی / Explore & Read» هستند.

2. **صفحه‌بندی محصولات (Products Pagination):**
   * در نمایشگرهای لپ‌تاپ و بزرگتر: **۹ محصول** در هر صفحه (گرید ۳ تایی در ۳ ردیف).
   * در موبایل: **۴ محصول** در هر صفحه (گرید ۲ تایی در ۲ ردیف).
   * شماره صفحات (1, 2, 3...) و دکمه‌های قبلی/بعدی مستقیماً از طریق Query Param در URL مدیریت می‌شوند (`?page=2`) تا باز کردن در تب جدید یا بوکمارک کردن به سادگی انجام شود.

3. **یکپارچگی دکمه‌ها و عناصر بصری:**
   * دکمه سوئیچ زبان (FA / EN) و دکمه مشاهده کاتالوگ در تمام صفحات یکدست، تیز و فاقد گردی شدند.

## ۴. مراحل گام‌به‌گام راه‌اندازی روی لینوکس (Linux Setup Guide)

### مرحله ۱: دریافت کد از گیت‌هاب
```bash
git clone git@github.com:MobinShekari84/Baldre-Website.git
cd Baldre-Website
```

### مرحله ۲: راه‌اندازی بک‌اند جنگو
```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_baldr
python manage.py runserver 127.0.0.1:8000
```
* **پنل ادمین جنگو:** `http://127.0.0.1:8000/admin/` (یوزر: `admin` / پسورد: `baldre2026`)

### مرحله ۳: راه‌اندازی فرانت‌اند Next.js
در ترمینال مجزا:
```bash
cd frontend
npm install
npm run dev -- -p 3000
```
* **سایت در مرورگر:** `http://localhost:3000`

## ۶. یکپارچه‌سازی پکیج دارایی‌های نهایی (Final Assets Integration)

در نشست اخیر، تمام دارایی‌های موجود در پوشه `Final/` پردازش، بهینه‌سازی و به وب‌سایت بالدر متصل شدند:

1. **تبدیل تصاویر به WebP طبق ضوابط پروژه:**
   - تمام تصاویر `Final/Product/` در ۳ فرمت (`Portraite 1`، `Portraite 2` و `Wide`) با حفظ کیفیت بالا و فشرده‌سازی تا ۹۰٪ به فرمت استاندارد `.webp` تبدیل و در `frontend/public/images/` ذخیره شدند.
   - نام‌گذاری تفکیک‌شده: تصاویر استودیویی (`baldr-prod-*-studio.webp`)، تصاویر لایف‌استایل معماری (`baldr-prod-*-arch.webp`) و بنرهای عریض (`baldr-wide-*.webp`).
2. **فعال‌سازی افکت تعاملی Dual-Image Hover:**
   - در کارت‌های محصول، وضعیت نرمال تصویر استودیویی با پس‌زمینه سفید خالص نمایش داده می‌شود و در حالت هاور به تصویر چراغ در محیط واقعی معماری سوییچ می‌کند.
3. **بهینه‌سازی و اتصال ویدیوی ۱۰۸۰p به عنوان پس‌زمینه هیرو:**
   - ویدیوی معماری `Screen_1080p.mp4` بهینه‌سازی شد و به صورت لوپ بی‌صدا (`/videos/baldr-screen-loop.mp4`) درآمد.
   - طبق درخواست کارفرما، گزینه‌های سوئیچ نور روز/شب (خورشید و ماه) به طور کامل حذف شدند و هیرو اکنون منحصراً این ویدیوی ۱۰۸۰p را به عنوان بک‌گراند تمام‌صفحه پخش می‌کند.
4. **جایگزینی کاتالوگ جامع ۱۵۱ صفحه‌ای:**
   - فایل ۶۱ مگابایتی رسمی کاتالوگ به `frontend/public/downloads/Baldr-2026-Catalogue.pdf` منتقل شد و جایگزین فایل تست قبلی گردید.
5. **استخراج نقشه‌های مقطع فنی (CAD Profile):**
   - نقشه‌های ابعادی پروفیل‌های آلومینیومی خانواده‌های **Vector SM** و **Vector R** به فرمت `.webp` در `frontend/public/diagrams/` استخراج و به مشخصات فنی محصولات لینک شدند.
6. **به‌روزرسانی دیتای بک‌اند و فرانت‌اند:**
   - مقادیر جدید در `baldrData.ts` و اسکریپت `seed_baldr.py` درج گردید.
7. **پالایش کاتالوگ و حذف تصاویر تستی:**
   - کاتالوگ محصولات صرفاً به ۸ محصول دارای تصویر اورجینال محدود شد و ۱۷ تصویر تستی پیشین به طور کامل از `frontend/public/images/` حذف گردیدند.
8. **عکس‌های Wide در سکشن دسته‌بندی صفحه اصلی:**
   - نوار دسته‌بندی صفحه اصلی منحصراً به تصاویر عریض و افقی (`baldr-wide-*.webp`) متصل شد تا تصویر چراغ‌ها بدون کراپ عمودی و با استایل `object-contain` به نمایش درآید.
9. **تست و اعتبارسنجی بیلد پروداکشن Next.js:**
   - دستور `npm run build` با تمام ۱۷ روت استاتیک بدون کوچک‌ترین خطای تایپ یا کامپایل با کد صفر به پایان رسید.

## ۷. گردش کار استاندارد و الزامی توسعه (Mandatory 4-Step Pipeline)

طبق دستور قطعی کارفرما و قانون ثبت‌شده در `.agents/rules/workflow-order.md`، تمام نشست‌ها و تسک‌های آینده باید دقیقاً این زنجیره ۴ مرحله‌ای را طی کنند:

```
[۱. خواندن فایل‌های Skill] ──► [۲. خواندن اسناد md-files] ──► [۳. اجرای دقیق Task] ──► [۴. آپدیت همزمان Skill و md-files]
```

1. **گام اول (Skills):** مطالعه مهارت‌های اختصاصی پروژه در `.agents/skills/` (شامل هویت برند، دستورالعمل فرانت‌اند Next.js، بک‌اند جنگو و کامپوننت‌های محصول).
2. **گام دوم (md-files):** مطالعه فایل‌های پوشه `md-files/` (به‌ویژه همین سند `SESSION_HANDOVER.md` و مستندات فنی متناظر) برای دریافت آخرین تصمیمات و معماری روز.
3. **گام سوم (Task):** اجرای دقیق خواسته کاربر با رعایت کامل هندسه تیز (`rounded-none`)، فرمت انحصاری `.webp`، فونت یکان‌بخ و کاتالوگ ۸ محصولی.
4. **گام چهارم (Update):** ثبت بلافاصله تغییرات و تصمیمات جدید در `md-files/` و به‌روزرسانی محتوای فایل‌های Skill در `.agents/skills/` به منظور همگام بودن دائمی دانش ایجنت.
